# 关卡数据驱动，独立网格规则

这个作品采用经典推箱规则，重点是可靠的游戏体验与制作工具。关卡、目录、视觉引用和体验参数使用可编辑数据；移动与推动规则由独立的 C# 模型统一执行，游戏与编辑器试玩复用同一入口。

选择 ScriptableObject 作为 Unity 内的关卡制作资产，使绘制、引用管理和保存保持直接。每次游玩复制独立状态，避免运行、撤销或重开修改内容资产；玩家成绩与稳定关卡 ID 关联，目录顺序只影响导航。新增运行时关卡修改后，成绩进一步按布局版本匹配，见后续决策。

没有采用 ECS：当前对象能力和规则组合固定，ECS 的实体管理、组件查询与系统顺序增加了接线成本。若以后出现大量可组合能力或需要并行模拟许多棋盘，再根据实际需求重新评估。

草稿与正式关卡通过目录收录关系区分；试玩使用显式上下文，不能写正式成绩。结构校验与可解性验证分开，可选的验证解法用于回归测试，布局修改后不再沿用旧解。
